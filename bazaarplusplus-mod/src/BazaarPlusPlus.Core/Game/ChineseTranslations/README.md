# 简体中文翻译优化

`zh-CN.overrides.json` 来自 item-description-resource 的 `mod-data/zh-CN/zh-CN.overrides.json`，数据修订 `2026-11-09.4`，提取基线为 2026-11-05 staging build 26419399。本文件整理其接入说明与《翻译约定》3.0，保留 BPP 维护需要的约定。

## 接入与更新

`ChineseTranslationOverrides.TryResolve` 按游戏提供的本地化键查找替换文本；桌面与 Android 的 `ChineseTranslationOverridePatch` 挂在 `LocalizationService.TryGetText(string, string, out string)` 之后、占位符及图标渲染之前，替换成功时同时返回查询成功。设置由 `ChineseTranslationSettingsDockEntry.Create` 提供，使用 `BppSettings.EnableChineseTranslationImprovementsConfig` 持久化。可见性和覆盖范围都取决于游戏语言 `zh-CN`，与 BPP 自身的中文模式分开。

数据是完整字典，更新时整体替换，不能只追加，否则已删除的改译会残留。JSON 编码为 UTF-8；键是描述本地化键，不是物品 GUID 或名称键。不要用中文全文、近义词或英文模糊匹配，不自行归一化原文后计算键。

平面字典不携带预期原文，运行时按键覆盖。游戏更新后须复核英文模板、官方中文与同键的全部引用；官方已修好的条目应删除，含义已变化的条目须重新审核。不得仅因 build 号接近便认定兼容。缺译、待审问题和证据不足的改译不自动加入字典。

切换开关影响后续本地化查询；已经渲染的描述在游戏重新生成时更新。游戏自己的翻译缓存和数据库保持原样，关闭开关后查询恢复官方结果。

## 改译原则

- 沿用自然中文，优先纠正对象、条件、次数、期限与数值来源，再统一同族措辞。英文用于参考，机制以完整物品及效果数据核实；不直译内部事件类名，不凭文字猜规则。
- 先读基础、附魔、任务及品质适用关系，再检查触发时点、来源、对象、操作、数值来源、期限和次数。一个键可能被多个物品及属性共用，全部引用都应适用，不能向无属性名的共享模板写死“伤害”等属性。
- 核实目标后，常规治疗、护盾、生命再生可省略“自己”；加速、充能可省略“己方”；伤害、灼烧、剧毒可省略“敌方玩家”；冻结、减速可省略“敌方物品”。自伤、反向效果、双方效果、具体物品身份、位置、数量、排除条件及特殊触发来源必须明确保留。这是措辞习惯，不能用来猜引擎目标。
- 区分动作、状态、属性和结算：“造成剧毒”与“中毒玩家”，“获得护盾时”与“拥有护盾时”，“治疗”与“物品治疗量提高”，“飞行期间”与“开始飞行时”不能互换。进入暴怒、暴怒期间、暴怒结束分别表达。
- 区分物品件数、满足的类别数、不同名称／模板数。“另一件”与“不同名称”不能混同；两次效果与一次双倍数值不同。首次、每场、前 N 次、永久、限本场等限定必须有证据且不能省略。
- 倍率表达明确：“变为原来的 X 倍”“提高 X%”“变为原来的 X%”各有不同含义。直接效果公式用“等量于”，属性增益公式用“提高，增幅等于”。保留总和、平均、逐件、最高值等聚合范围。

## 术语、数值与格式

- Legendary 用“传说级”，non-Legendary 用“非传说级”；Multicast 用“多重释放”，Aquatic 用“水系”；怒火是资源，暴怒是状态。
- 一般定量加成用“获得”，如物品获得伤害、护盾、价值，玩家获得护盾、金币、怒火。永久成长保留“永久获得”；无属性名的共享 Token 保持无属性名。
- 命名量值用自然动词：治疗量、生命再生量、充能量“提高”，比例用“价值提高 X%”，扣减用“降低／减少”，时长用“延长／缩短”。不要写“获得 -X 伤害”或“获得 X 秒冷却”。
- 加号只用于多重释放加成、真正数学表达、原带符号数值、阈值记号及引擎融合预览。普通结果不写“获得 +”或“提高 +”。条件、事件及累计语境仍保留动词，如“每获得 10 点节奏”“已通过此效果获得 N 多重释放”。
- 保留支付、消耗、失去及动作的施受关系；不能把“消耗金币”改为“损失金币”。物品护盾输出与玩家直接获得护盾要靠具体承受者区分。
- 区分输出持续时间与受到效果的持续时间。百分比单位和相对增幅不同，不能凭名称含“率”猜运算，也不能把 50 自行改为 0.5。装填数量以实际配置为准，无数量时不推断装满。
- 保留必要逻辑连接词、复句与换行；同模板句末格式一致，不做全库“的／就／便”替换。

## 占位符与验证

原样保留 `{ability.0}`、`{aura.2.mod}`、`.targets`、`.ref`、`{ability.e1 ?? aura.e2}` 等表达式及出现次数。固定数字、百分号、目标数量、左右、首次、最多等都须逐项核对，不自行添加占位符或把说明变量 X 写入正式译文。

图标可能由数值 Token 或关键词生成，不因缺少 `<sprite>` 就补标签。保留游戏的数值解析及 `??` 分支行为，不通过补 0 或改运算修文案；也不要匹配已经展开数值或最终富文本的句子。关注 Token 自带符号及负数，避免重复符号。

每次新增规则都应检查一个真实例子和一个不应受影响的反例，同时走查全部共享引用。自动检查不能代替读完整物品；图标、单位重复、折行、融合预览与负值显示需在实际游戏界面验证。
