# Android Host

`BazaarPlusPlus.Android` (`net10.0`) is the Android Host (root `CONTEXT.md`, Host). It is a MelonMod (`src/BazaarPlusPlus.Android/Host/AndroidMod.cs`) compiled against the Interop Snapshot and the Loader Release (`build/InteropPath.props`), never against `Managed/`.

## Shape

- `Host/` owns the loader entry, the `BppLog` exit over MelonLogger (`MelonLogSink`, scope `Android`), the settings store over `MelonLoader/UserData/BazaarPlusPlus.cfg` (`IniSettingsStore`) and the Data Root (`AndroidPaths`): `BazaarPlusPlusV6` beside the MelonLoader base directory.
- `AndroidComposition` builds Core's `CoreComposition` over that Data Root and registers the record chain and the Bundle path, in start order: Core's `RunLifecycleModule` and `RunLoggingModule` over the IL2CPP probes in `GameInterop/`, then Core's `BundleSealCoordinator`. Core's `UploadPump` starts after them and is ticked from `AndroidMod.OnUpdate`; it sends each sealed Bundle to `POST /bundles` with the `android-aarch64` User-Agent token. Bundles are Run-only: the host takes no end-of-run screenshot.
- `AndroidPvpBattleCapture` frames each PvP battle from the net messages (opening `PVPCombat` game sim, combat sim, next game sim), as the desktop's `CombatReplayCaptureService` does. At the opening it takes the four board captures (`AndroidPvpBattleSnapshots`, in Core's `PvpBattleCardSetDocument` shape); it serializes each message as it arrives (`AndroidReplayMessages`), saves the Replay Payload to `CombatReplays/`, then the battle through Storage's `PvpBattleSqliteStore`.
- The Bundle composer is Core's `RunPayloadComposer`; the host supplies only `AndroidPvpBattleEvidence` (card enum values, Replay Payload check).
- `Patches/` install per class under the `[Android] PatchMode` setting (`enabled`, `observe`, `disabled`). A class that fails to install degrades only itself. `NetMessageReceivePatch` is the message intake (run initialization, battle capture); `CombatSimulatePatch` publishes `CombatSimObserved`.
- In the `enabled` mode the host adds the interaction features, which touch replaces the desktop's hotkeys for. `Ui/AndroidTouchUi` is a BPP button on the left edge that opens one panel: Settings switches `[Android] UpgradePreview` and `[EnchantPreview] Mode` (`Always` or `Off`; the desktop-only `AutoOnPedestalChoice` reads as `Off`, since the host has no pedestal probe) and shows the game-update row; History lists the Data Root's Runs and the selected Run's battles through `History/AndroidHistoryReader`, read-only. `[Android] TouchMenu` hides the button.
- `GameInterop/AndroidUpgradePreview` puts the item whose tooltip a tap opens into the game's own upgrade preview (`CardController.EnterUpgradePreview`), which renders its next-tier values; it holds at most one controller and releases it when another card opens, the tooltip closes, the switch turns off, or a scene loads. `GameInterop/AndroidEnchantPreview` renders each enchantment's text against the game's lock-mode preview card (`CardExtensions.ApplyPreviewEnchantment`) and appends it to that render's passive block.
- `Lobby/AndroidVersionCheck` runs on every `MainMenuScene` load: Core's `MainMenuSelfUpdate` over the `android-aarch64` Platform Release Manifest ([self-update.md](self-update.md)), the status on the version label, and, when the build number in the manifest's `game.gameVersion` is above the one in the running game's `Application.version`, the game-update row that opens the APK's URL.
- Shared code comes from Core's `net10.0` output, with Storage and ModApi through it; the host links no Core or desktop source. `just mod::android-deploy` pushes the build to the `melonloader` paths of the Payload Inventory (root `CONTEXT.md`), read through the generated `Payload.targets`: BPP's assemblies into `MelonLoader/Mods/`, third-party ones into `MelonLoader/UserLibs/`, the Updater into `MelonLoader/Plugins/` ([self-update.md](self-update.md)).

Not on Android yet: Ghost import, replay playback, favorites, and the native boards of the desktop History panel; Collection and Live Build, which rent native card prefabs the host has no adapter for; and replay retention (`ReplayPayloadMaintenanceService`), so `CombatReplays/` grows with every recorded battle.

## Build and test

`tests/AndroidHost.Tests` fails if the compiled host references BepInEx or a desktop assembly, or defines a BPP type outside `BazaarPlusPlus.Android` (a linked source). It runs in `just mod::test-core`, the suites that need no Managed snapshot, and in the `mod-android` CI lane, with the two goldens on the `net10.0` binding this host ships: `tests/BundleV6Codec.Net10.Tests` (the Run segment) and `tests/RunLoggingPipeline.Net10.Tests` (the history database), each of which must reproduce the desktop binding's goldens byte for byte. `just mod::android-*` drives one device, and `just mod::android-setting <section> <key> <value>` switches one feature for an on/off capture; `just mod::android-smoke <mode>` asserts injection, hook hit, and feature on it, and the self-hosted `mod-android-smoke` lane runs it nightly ([development guide](../../../docs/development.md#android-冒烟)).

## Gotchas

- SQLite's native `libe_sqlite3.so` must sit in the APK's `lib/arm64-v8a/` (the Android release's injection step adds it). External storage is `noexec`, so `UserLibs/` cannot carry it; a deploy to an APK without it fails at the first store open.
- A `T?` an IL2CPP getter returns arrives as an `Il2CppSystem.Nullable` proxy over a boxed `T`, whose `HasValue` and `Value` are wrong: every player attribute read as 0 and opponent ranks came out shifted. Read the dictionary or field behind it, or go through `AndroidGameIds.Unboxed`; the board captures read every card's section, socket, tier, size, and enchantment that way.
- Every Android store opens the database with `AndroidComposition.DatabaseOptions` (`DELETE`): a Storage store given no options would switch the file to WAL. Core's seal coordinator, upload pump, and composer therefore take the options as a required argument. `DELETE` keeps one self-contained file that `adb pull` reads whole. WAL opened, wrote, and read back on the emulator's FUSE Data Root, but that is one process on one device, not a reason to switch.
- A message here is an IL2CPP proxy, which the managed MessagePack cannot read: Replay Payload bytes come from the game's own serializer (`Il2CppMessagePack.MessagePackSerializer.Serialize<T>` with the concrete message type and `MessagePackConfig.Options`, as the desktop's `PvpReplayPayloadFactory`), and each is decoded back before the payload is kept. That runs on the main thread only. The seal worker is a pool thread that must not call into IL2CPP, so `AndroidPvpBattleEvidence` checks a payload for well-formed MessagePack and resolves card enums from the interop enums, which are managed.
- Harmony can replace the IL2CPP `CombatSimHandler.Simulate` `Task`, as the desktop's `CombatSimPatch` does for replay: a prefix that returned an `Il2CppSystem.Threading.Tasks.TaskCompletionSource<Object>`'s `Task` held the combat until BPP completed it from `OnUpdate` after running the original 3 s later, and the game awaited it and finished the fight (#360 spike, removed after the measurement).
- An unreadable `BazaarPlusPlus.cfg` still installs the hooks (`PatchMode` falls back to `enabled`) but starts no record chain: `android.record_chain.start_failed` follows `android.settings.load_failed`, and nothing is recorded, sealed, or uploaded until the file reads.
- The startup `android.build_channel.probe` logs `server_option=missing` on every online build, the Online answer: as on desktop, only the PTR fork of `Config` declares `ServerOption`. It does not show whether Il2CppInterop exposes the nested type; only a PTR or staging Android capture can.
- A managed `MonoBehaviour` exists in IL2CPP only after `ClassInjector.RegisterTypeInIl2Cpp<T>()`, and the type needs the `(IntPtr)` constructor; `AddComponent<T>` on an unregistered type fails. Unity calls the injected `Update`. Its `StartCoroutine` takes an `Il2CppSystem.Collections.IEnumerator`, not a managed iterator: run a managed coroutine through `MelonCoroutines.Start`, where both `yield return null` and `WaitForSeconds` resume.
- `TooltipParentComponent.HideCardTooltipController` returns early while a card-to-card transition runs, and tapping a second card calls it during that transition. Releasing the upgrade preview on every call left the new card's tooltip showing next-tier values with its controller out of preview, so `AndroidUpgradePreview` releases only when the tooltip's `CurrentCard` was cleared.
- The game's rendered tooltip text carries its own `<line-height=1.6em>` and `<size>` tags for full-size text. Appended at reduced size, they kept full-height lines and the enchant list overflowed a phone tooltip; `AndroidEnchantPreview` strips the line heights and scales the sizes (`ItemEnchantPreviewText.ScaleInlineSizes`).
