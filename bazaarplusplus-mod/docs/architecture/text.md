# Typography, Localization, Voice Subtitles, And Supporters

Every BPP surface gets its text rendering from one adapter over the game's own font assets. Localization resolution, voice-over subtitles, and supporter attribution all sit on top of it.

`BazaarPlusPlus.Localization` is the localization resolution engine. The `L` facade is installed at plugin startup with language and locale-mode providers, then resolves `LocalizedTextSet` values against current language and Chinese locale mode (`src/BazaarPlusPlus.Localization/L.cs`, `src/BazaarPlusPlus/Plugin.cs`).

BPP does not embed, extract, select, or create an operating-system font. Every feature calls the single `NativeGameTypography` adapter and never receives a raw `Font`, `TMP_FontAsset`, fallback chain, or `PanelTextSettings`. The adapter keeps the renderer-specific implementation private: native TMP labels retain their donor primary font and material while a cloned primary receives the corresponding game fallback chain; BPP-created uGUI uses an opaque prepared binding over the game's loaded sans primary plus the complete ordered `zh-CN` Static → SecondSet → Dynamic chain; UI Toolkit uses a panel-local scope over the Dynamic asset's packaged `UnityEngine.Font` source because it cannot consume TMP assets directly (`src/BazaarPlusPlus/GameInterop/Fonts/NativeGameTypography.cs`).

`PrepareOwnedText` preserves fail-before-create behavior for BPP TMP trees. Its binding establishes orthographic uGUI measurement before activation: TMP otherwise measures a hidden tree at one-tenth scale until `Awake`, causing eagerly cached supporter widths to collapse. Text rectangles must also fit the actual glyph height; an ellipsis overflow on the first glyph can clear the entire mesh. These behaviors require Unity runtime measurement rather than pure layout tests. `EnsureNativeTextCoverage` augments donor TMP without exposing how the chain is selected. `TryAttachPanel` atomically installs a panel-local `PanelTextSettings` bound to the game's sans body font; its scope is the only code that sets both `unityFont` and `unityFontDefinition`, checks external text against the actual selected font, and releases the panel settings. OS and emoji fallback remain disabled, global game settings are never mutated, and all Unity mutation is guarded to the initialization thread. The adapter restores donors, prunes destroyed donor bindings, invalidates outstanding scopes, and releases every owned handle/clone at teardown (`src/BazaarPlusPlus/GameInterop/Fonts/NativeGameTypography.cs`).

`Game/VoiceSubtitles` renders in-game voice-over subtitles (the BazaarLine integration): `VoiceSubtitlesModule` plus a `GameInterop/VoiceSubtitles` bridge module observe game VO playback (`src/BazaarPlusPlus/BppComposition.cs`), and `VoiceLineDisplayDispatcher`/`VersionLabelScanner` mountables render cues. The line catalog is supplied under its stable manifest name by the shared remote-data build pipeline; `VoiceLinesCatalogFactory` contributes the parser and feature logging policy to `RemoteEmbeddedCatalog<VoiceLine[]>` (`src/BazaarPlusPlus/RemoteEmbeddedData.targets`, `src/BazaarPlusPlus/Game/VoiceSubtitles/VoiceLinesCatalogFactory.cs`). The feature module owns this catalog for its own lifetime and disposes it before clearing the static line catalog, so a late remote continuation cannot republish after `Stop()` (`src/BazaarPlusPlus/Game/VoiceSubtitles/VoiceSubtitlesModule.cs`). The feature is gated by a master toggle (default OFF) in `BazaarPlusPlus.cfg` `[VoiceSubtitles]` (`src/BazaarPlusPlus/Game/VoiceSubtitles/VoiceSubtitlesGate.cs`, `src/BazaarPlusPlus/Core/Config/BppConfig.cs`), with a four-state Subtitle Mode dock row registered via `VoiceSubtitlesSettingsDockEntry.RegisterAll`. Subtitle labels preserve the version-label donor font/material when it already covers Chinese. If it does not, mounting waits until the game's Chinese font configuration exists, then renders the Chinese row through `TextMeshProUGUI` using the game sans primary clone with its complete Chinese fallback chain and without synthetic bolding (`src/BazaarPlusPlus/Game/VoiceSubtitles/VersionLabelScanner.cs`, `src/BazaarPlusPlus/Game/VoiceSubtitles/VoiceLineDisplay.cs`).

Supporter attribution is a game-side display module, not a generic sampling utility. `BPPSupporters.SampleMany()` and `Sample()` delegate to `BPPSupporterCatalog.GetCurrentEntries()` and `BPPSupporterSampler` (`src/BazaarPlusPlus/Game/Supporters/BPPSupporters.cs`). `SupporterCatalogModule` is the composition-owned third consumer of `RemoteEmbeddedCatalog<T>`; fixed-list mode bypasses factory/warm entirely, normal mode loads the game-root cache or embedded seed and queues the remote refresh, and a missing snapshot is latched for five minutes before access may schedule another warm (`src/BazaarPlusPlus/BppComposition.cs`, `src/BazaarPlusPlus/Game/Supporters/SupporterCatalogModule.cs`). The static `BPPSupporterCatalog` is only config, fixed-list policy, and the published snapshot projection; the module disposes the catalog before clearing that projection, so late callbacks cannot republish (`src/BazaarPlusPlus/Game/Supporters/BPPSupporterCatalog.cs`, `src/BazaarPlusPlus/Game/Supporters/SupporterCatalogModule.cs`).

HistoryPanel, CollectionPanel, and LiveBuildPanel consume supporter samples. HistoryPanel and LiveBuildPanel share `BPPSupporterNativeAttributionRow`, which applies `NativeGameTypography` to fixed-size literal names, tier colors and gradients, localized attribution, and the support action; History uses an inline row and LiveBuild uses a vertical list that gives each name its own line (`src/BazaarPlusPlus/Game/Supporters/Ui/BPPSupporterNativeAttributionRow.cs`). Collection uses a UI Toolkit attribution row. In the UI Toolkit row, every prefix, name, separator, suffix, and action element pins both `unityFont` and `unityFontDefinition` to the same game source font so Latin and CJK names cannot diverge through a child theme font definition; supporter names use the font's normal weight rather than synthetic bold (`src/BazaarPlusPlus/Game/Supporters/Ui/BPPSupporterAttributionRow.cs`). This module should stay separate from feature-specific UI behavior.
