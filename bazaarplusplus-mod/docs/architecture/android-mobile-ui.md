# Android Mobile UI

How every BPP surface on the Android host fits a phone: the native-style panel shortcuts, Collection, History (with its Ghost section and replay entry), Ten-Win Builds, the rows BPP adds to the game's settings dialog, and the upgrade and enchant previews in the game's own tooltip. The host itself is [android-host.md](android-host.md); the reason for one shared frame is [ADR-0018](../adr/0018-android-touch-surfaces-share-one-frame.md). The Mono host on iOS ports every one of these surfaces and follows the same conventions ([ADR-0024](../adr/0024-mono-host-touch-surfaces-on-mobile.md)); its combat clock reads the vault through `GameInterop/Touch/TouchVaultBounds`.

The ports are moving, pair by pair (issue #701), into one Mobile UI tree, `src/BazaarPlusPlus.Mobile/` (namespaces `BazaarPlusPlus.Mobile.*`), which both host projects compile ([ADR-0025](../adr/0025-one-mobile-ui-source-for-both-hosts.md)). Code there reaches its host only through the Mobile Platform Port, `IMobilePlatformPort`, which `AndroidMobilePlatform` and `TouchMobilePlatform` implement: the Android host installs its port at startup, the Mono host only on a mobile platform (`TouchPlatform.IsMobile`). Each host's `GlobalUsings.cs` maps the TextMeshPro namespace and names the game's card preview type `GameCardPreview`. `Mobile/Ui/` holds `ScrollTracker`, `ArtImage`, `InspectionText`, the kit (`UiKit`, `ChipFlow`, `NativeSkin`, `PortraitView`, `KeywordSprites`, `TouchScreen`, `UiActions`) and `InGameTheme`, which `just design::build` generates there for both hosts. `Mobile/LiveBuild/` is Ten-Win Builds, `Mobile/Collection/` is Collection and `Mobile/History/` is History on both hosts (below); each registers through the port's overlay registration (`MobilePanelHandle`, panel ids `live_build`, `collection` and `history`, no toggle hotkey, so on iOS the game's keybind settings list none of the three), which also ticks it, and reaches host services through Core ports each composition binds: `ISupporterRotation` for the supporter credit, for Collection its card catalog, run reads and encounter state ([collection.md](collection.md)), and for History its `HistoryPanelDependencies` and card templates (`IHistoryCardTemplates`). The rest of this page names the Android twins still in the host.

## The shared frame

`Core/Ui/TouchMetrics` turns the screen (size, `Screen.dpi`, `Screen.safeArea`) into the overlay canvas's units. The canvas scales with the screen's height (`UiKit.CreateOverlayCanvas`), so one dp is a different number of canvas units on every screen; layouts always ask `TouchMetrics.Dp`, `Sp` and `Target`, never a constant in canvas units. A device that reports no density reads as `TouchMetrics.FallbackDpi`.

`Core/Ui/TouchChrome` is the frame every surface lays out in: the sheet (the safe area less a margin), its body (less a padding), the gap, the header row, the type scale, and the close button. Each panel's own layout (`CollectionTouchLayout`, `HistoryTouchLayout`, `LiveBuildTouchLayout`) starts from it and places only its own content. `TouchChrome.Inspect` is the tap-to-inspect sheet all three card panels share (`TouchInspectLayout`). All of it is Unity-free and tested in `tests/SettingsDockCore.Tests/TouchChromeTests.cs` on the screens below.

## Conventions

- **Targets.** Every button, tab, chip, row, and search field is at least `TouchMetrics.MinTargetDp` (48 dp) tall, and a close button is `TouchChrome.CloseWidthDp` wide. A card socket a tap picks is a target too: Ten-Win Builds keeps every socket at least 48 dp wide, and where its boards beside the overview would leave one narrower, or the overview's column too short for the metric cells (`LiveBuildTouchLayout.MinMetricCellDp`), as on a dense screen, it stacks (`LiveBuildTouchLayout.Stacked`): the final build's title band and close stay as a header and the boards, then the overview, scroll under it. The game's own settings dialog keeps its native rows and grows their hit areas instead (`TouchMetrics.MissingTargetPixels`, android-host.md).
- **Text.** No text on a BPP surface is under `TouchMetrics.MinBodySp` (12 sp); `TouchMetrics.Sp` refuses less. Text BPP adds inside the game's own tooltip follows the tooltip instead (Previews, below). The scale is `TouchChrome`'s: a title, a card name, a button or chip, body text, in falling order. A `UiKit` button's label sits `TouchChrome.LabelInsetDp` in from either side, the same dp on every screen; History's buttons keep their own palette's padding. A chip's label shrinks to fit (TMP autosize) between the button and body sizes, then ellipsizes; it never wraps. The Collection inspection measures its labels at body size first and drops chip columns until the widest shows whole (`CollectionTouchLayout.InspectChipColumnsFor`), so an enchantment name is never cut; a filter chip whose label would not fit its span widens across more columns (`TouchChrome.ChipSpan`). Text that would not fit grows its band (History's board messages) or takes a shorter touch label (Ten-Win Builds' `LiveBuildPanelText.CandidateTouchTag`). A sideways-scrolled strip holds only chips: a note in one runs past the screen's edge, so it wraps in a column with room instead (History's Ghost cloud note, in the rail column Ghost leaves empty, `HistoryTouchLayout.CloudNote`).
- **Safe area.** Everything lays out inside `TouchMetrics.SafeArea`, so a cutout or rounded corner never covers a control. `TouchHudLayout` positions the BPP icons in a corner around the run's settings button: Collection below it (`ShortcutBelow`), Ten-Win Builds left of it (`ShortcutBeside`); in a run on a screen narrower than 16:10, where the nearer board reaches up to the gear, both in a row left of it (`ShortcutInRow`). Collection also shows by the lobby and hero-select settings button; Ten-Win Builds shows in a run only. History has no icon: its entries live in the game's own menus (android-host.md). Their circular artwork is drawn at the gear's own size, icon where the gear's icon sits, and each target is at least that size. They hide during combat, native card inspection, popups and BPP panels. `TouchHudLayoutTests` checks safe-area fit and non-overlap, including the combat clock beside the vault, or as one row centred in the band above a lowered board (or under the vault) on a nearly square screen.
- **Sheets.** A panel is a full, opaque sheet: title top-left, close top-right (`TouchChrome.Close`), content below. A dialog closes from the same corner of its own body (`TouchChrome.CloseAt`). Every close button is `UiKit.CloseButton` or, on History's own palette, its `UiKit.CloseGlyph`.
- **Back key.** Every surface closes on the back key, top-most first; the chain and how it reaches BPP before the game's escape menu are [android-host.md](android-host.md)'s.
- **Off switch.** A Main Overlay Panel switches off from its native settings row, not from inside the panel: History closes with its X, and the settings row then turns it off. History's More dialog keeps only the database check switch the account link.
- **No hover, right-click, or hotkeys.** A tap replaces hover: tapping a card opens the inspect sheet with the card enlarged and its text beside it; a tap outside the info column, its close button, or the back key dismisses it. Every action the desktop puts behind a hotkey or a context menu is a visible button.
- **Scrolling.** Ten-Win Builds fixes the recommendation and one lower board on ordinary landscape screens; a button beside the lower board cycles current board, stash and shop without clearing candidates. Both boards have native frames with inset card and tag areas. Recommendation paging joins the board switch in the right operation column; hero identity moves into the recommendation title. A compact library row sits below the metrics and above recommendation paging: muted status on the left opens scrollable corpus details (including freshness and errors), and a native framed Update button on the right refreshes the library. Paging and the board switch expand into the remaining height, with the final switch aligned to the lower board frame rather than the scroll viewport. The board column needs no separate switch band. Empty recommendation guidance occupies the upper board itself. Its dense arrangement scrolls the selected board and overview under the header. Lists and grids scroll by drag with inertia (`UiKit.VerticalScroll`, the Collection grid's included; History's own palette has `TouchHistoryUi.Scroll`); the Mobile UI's `ScrollTracker` logs each finished gesture (`touch.history.scrolled`, `touch.collection.scrolled`) with its distance, peak speed and coast frames.
- **Columns from width.** A card grid chooses its column count from its width, never a fixed desktop count: `CollectionTouchLayout.GridColumns` keeps a small item's column and a skill's square above a readable minimum, up to the desktop's count, and never fewer columns than a large item spans. `CollectionGridLayout.Build` takes that count; the desktop overload keeps `CollectionGridConstants`.
- **Relayout.** A surface lays itself out again when the Mobile UI's `TouchScreen.Key` (size, density, safe area) changes, and renders the same state into the new tree; an open panel stays open (`touch.collection.relaid_out`, `android.ui.touch_layout`). Collection closes an open inspection first (`touch.collection.inspection_closed reason=relayout`), returning its card. History reopens an open note dialog on its unsaved draft (`touch.history.relayout note_draft_kept=true`); a scene change, which keeps the view, leaves the note open on its draft (`touch.history.scene_changed note_draft_kept=true`). An open Ten-Win Builds or Collection, each of which rents its cards again on a relayout, waits for the key to hold still and for no card to be setting up (Core's `TouchRelayoutDebounce`, capped so a stuck setup cannot pin the old layout); `touch.live_build.relayout` and `touch.collection.relaid_out` log the frames it held. Opening on a changed screen lays out at once. Each panel's view goes through Core's `TouchViewSlot` (`src/BazaarPlusPlus.Core/Ui/TouchViewSlot.cs`): the old view is forgotten and dropped before the new one builds, and the key is recorded only once the build returned. So when a build fails, on a relayout, on opening, or for Collection's first tree, no panel keeps a destroyed view: the build destroys its partial tree, the panel logs `touch.collection.relayout_failed`, `touch.live_build.layout_failed` or `touch.history.layout_failed`, reads closed (a failed relayout requests the host's close, so the touch launcher comes back), and builds again on the next open. The recovery stays the panel's own: Collection's close ends its view state, Ten-Win Builds closes its state, History's overlays go with the view.
- **History header.** History keeps section tabs, one supporter credit that opens the sponsor page, More and Close. The run archive sizes its rows to show three complete runs in the initial viewport while keeping the touch-target floor; additional runs remain drag-scrollable. It offers no hero, outcome or day filters; the archive uses the default unfiltered coordinator state. The supporter credit shares Collection's catalog and samples once per opening, with a late catalog arrival filling the initial sponsor label.
- **Native look.** `GameInterop/AndroidNativeArt` borrows popup button sprites and tooltip frame/TagFrame art, which the host hands the Mobile UI's `NativeSkin` through its port; the skin applies them to Collection, History, Ten-Win Builds, the tooltip's touch previews and the combat clock without copying native callbacks. The sprites are cached process-wide: `FindObjectsOfTypeAll` runs again only for a pair that is missing or collected, and only that rescan logs `android.native_art.skin_loaded`; each surface keeps one skin until `NeedsRefresh`. The round shortcut frame is read, at rest, from the gear `Ui/AndroidTouchUi` already anchors to (`AndroidNativeArt.RoundArtFor`). Panels keep opaque backing beneath transparent frame art. History's sheet, dialogs and inputs draw only the art's border (`NativeSkin.Frame` with `borderOnly`), so each fills its interior once, and History's backdrop covers only the margins around its sheet, as four bands, rather than the whole canvas under it. Decorative images take no touches, and missing sprites fall back to the host palette. Reopening a panel with missing or destroyed art rebuilds its view. History keeps its warm backing and status palette, and its dimmed actions remain tappable where the model supplies an explanation. The Mobile UI's `PortraitView` shares Collection's framed hero crop with History archive rows; rebinding a reused row invalidates its previous portrait request. The Mobile UI's `InspectionText` scrolls long History and Ten-Win Builds descriptions at body size instead of truncating them.
- **In-game previews.** The upgrade switch controls the existing next-tier projection inside the native tooltip, at the game's own text size. Its initial state follows the Android upgrade setting. Under `[EnchantPreview] Mode` ON, or AUTO while an enchant pedestal is offered, the enchantment effects are listed expanded in the native tooltip's main text below the passive text, one line per enchantment at the current quality, where a player reads them without a tap or a scroll. The upgrade switch, and the enchantment switch for an item whose main text lists none, use Collection's toggle rows inside the native right-side description scroll; those enchantment effects expand below their switch, merge current-and-higher-quality values with Collection's formatter and colour the enchantment names. Body text follows the shared touch floor. Replacing or dismissing the native tooltip collapses the enchantment section; Back collapses it before the native tooltip handles another Back. Native pedestal-owned upgrades are never disabled by BPP.
- **Combat clock.** A plaque in the native button's opaque dark-brown sits right of the vault and spans the vault frame's height, so its top and bottom edges line up with the board. The vault is the player's bank, an equipped cosmetic (`BankToyController` under `BoardManager.playerBankAnchor`); it is board meshes rather than canvas UI, so `GameInterop/AndroidVaultBounds` projects its framed platform mesh (`Bank_Platform_SM`, not its slightly larger `Platform_Shadow_SM`) through the board camera, as the desktop bar reads the hero portrait, and `TouchHudLayout.Playback` places the plaque beside that box. The platform holds still while the coin pile on it changes with gold; a bank without one falls back to its hover boxes (the pot's `_bankCollider` and the income and gold plaques' colliders), which sit a few pixels up and left of the art; the stash cosmetic (`activeStorageToy`) is the box at the board's other end. As on the desktop, no vault on screen means no plaque: the main menu, which has an active run to resume but no board, shows none, and a read that is off the canvas, left of center or shorter than a touch target (`TouchHudLayout.FitsBesideVault`) hides it too. The vault is read every few frames while the clock shows; a vault or screen that moves lays the plaque out again once the new place holds still for two reads (`TouchRelayoutDebounce`), and a clock shown again after hiding lays out at once; `android.combat_status.layout` logs the box. It hides while the native card drawer shows an inspected card, and its canvas sorts just beneath that drawer. Time fills the upper row with tabular digits; a gold rule separates it from a shorter lower row split by a vertical rule into speed (left) and pause/resume (right). The two hit areas keep full touch-target size by extending below the plaque to the screen edge rather than into the time row. The default-on **Combat timer** switch in native settings controls visibility. As the desktop bar, it shows for the whole run or replay, not only during a fight: before the first fight it reads `0:00.00`, after one it keeps that fight's final time until the next starts at zero, and outside a fight the time fades to muted ink and pause/resume dims, while speed stays tappable and sets the next fight's pace. While it is hidden beneath a panel, popup or inspection it is built hidden ahead, once per scene (`android.combat_status.layout ahead=true`), so the frame it reappears on does not build it; a plaque built before the native art loaded is built again when first shown. Tapping speed cycles the three supported speeds using the shared speed setting. It hides beneath Main Overlay Panels and native popups and clears on scene changes. **Detailed Preview** controls both quest and encounter previews through one native settings toggle. It never counts background wall time.

## Screens

The tests cover a 20:9 phone (2400x1080 at 420 dpi, with and without a cutout; Ten-Win Builds also at 480, 560 and 640 dpi, where it stacks), a 16:10 tablet (2560x1600, with and without the emulator's 91 px top inset), a 16:9 phone (1920x1080), and a device that reports no density. The device evidence covers the first two. Keep a separate landscape AVD for each ratio and select it with `BPP_ANDROID_SERIAL`; changing one emulator's `wm size` mixes device configuration with layout evidence. Before judging a panel, run `just mod::android-screen-check <run>` on that panel. It saves the screenshot and display metadata and rejects portrait screenshots, size/density overrides, or a mismatch with the last logged Unity screen. It never changes the device. `environment.json` records the last logged Unity density and safe area when available; `display.txt` keeps Android's display state. A passing check establishes the display baseline, not visual correctness: inspect the screenshot for sideways content, clipped rows and alignment.

Use `just mod::android-check` for the serial build/test gate. The build and test script entry points share a checkout-local lock because they write the same `bin/obj` outputs; run another checkout to work independently. Each gate saves full logs and a `result.json` with the revision, dirty-worktree flag and exit codes under `artifacts/validation/`. A failed step stops the sequence. After an interrupted process, the next run's lock error names the lock directory; its `owner.json` records the holder, so confirm that process has stopped before removing the directory.

## Gotchas

- The overlay canvas scales with height, so a 16:10 tablet has fewer canvas units across than a 20:9 phone of the same height: a layout that fits the phone by canvas units can overflow the tablet. Lay out in dp from `TouchMetrics`, and test both ratios.
- A rented card carries its own `Canvas`, so a `RectMask2D` does not clip it: a scrolled card list draws first and opaque bands above and below it hide the cards past its edges, and the inspect sheet is opaque under its info column.
- `RectTransform.rect` of a stretched child is valid as soon as its parent has a size, so a flow that measures wrapped text (`ChipFlow.Note`) needs its parent placed first.
