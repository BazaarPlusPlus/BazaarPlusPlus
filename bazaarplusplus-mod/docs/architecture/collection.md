# Collection Panel

The full-screen Item/Skill catalog: filter state, the pure view-state reducer, grid virtualization and cell fit, filtering rules, the Day gate, the source catalog, and card view models.

The host-free half lives in Core under the same `BazaarPlusPlus.Game.CollectionPanel.*` namespaces (`src/BazaarPlusPlus.Core/Game/CollectionPanel/`): filter state, the view-state reducer, the filter engine and query, search, facet availability, the source catalog parser and offer pools with the embedded `collection-sources.json` (`EmbeddedCollectionSourceCatalog`), the open lifecycle (`CollectionViewState.Open` over `CollectionOpenFacts`), the view model, panel text, the ability-placeholder formatter (`CollectionAbilityPlaceholders`), the tier-text merge, and the grid geometry (`Grid/`: layout, pixelization, retention plan, fit math, bounds cache, material LRU, constants). It speaks card facets, not game enums (ADR-0015). Each host keeps its view, its native card binding, its patches, and its game-typed projection to `CollectionCardVm`. The desktop host's projection is `CollectionCardVmProjection`, which maps templates through `DesktopCardFacets`; its ports are `StaticCollectionSourceCatalog` (the embedded catalog against this build's heroes) and `CollectionDayTierSource` (the GameData day-tier resolver). Both hosts classify templates through Core's `CollectionCardEligibility` and take the visible index span from `CollectionGridLayout.VisibleIndexRange`.

The desktop Collection draws on its own calm tokens, not the warm ones the other panels use (ADR-0026, amended 2026-11-12): the ground and the grid occluders are one opaque `ingame-neutral-ground`, so a card scrolled past the viewport never shows its edge; filter cards and the grid are flat `ingame-neutral-surface` framed by an `ingame-neutral-rule` hairline whose strength ranks them; chips, fields and buttons rest on `ingame-neutral-chip` in `ingame-neutral-ink` and select on `ingame-select` with an `ingame-select-rule` border, with hover and press derived in `CollectionPanelView`. Nothing is drawn on the Desktop UI kit's plates. Quality chips keep the `ingame-tier-*` colours as text. Tag and keyword chips keep the game's keyword colour on their icon and text and select on `ingame-select` like every chip. The supporter strip (`BPPSupporterAttributionRow`) is a flat `ingame-neutral-ground` strip with a neutral sponsor button.

The desktop folds the merchants (and trainers) whose click shows the same cards into one cell, a **Source Group** (`CollectionSourceGroup`). Core's `CollectionViewState`, built with `foldSources` by the desktop host only, keys each visible source on what its click shows (`CollectionSourceFoldKey`: its offer pool for the effective hero, whether it skips the Day gate, and on Skills whether it skips the hero filter) and publishes `SourceGroups` beside the flat `AvailableSources`, which the touch panel keeps reading. Pools resolve for the fold only against an accepted, non-empty catalog: against an empty one every pool is empty and the pool cache would keep that. A folded cell shows the selected member, else the member the run met, else the first member, with a count badge. Its click opens a strip of its members under its line (`CollectionSourceFoldExpansion`); a member's click toggles that member's own key and closes the strip, and a second click on the cell, Escape (the panel's modal to the Overlay Panel Host) or a click elsewhere closes it. The selection, the stored selection and the encountered set always name a member's own source key.

The touch Collection is the Mobile UI's `src/BazaarPlusPlus.Mobile/Collection/` (ADR-0025), which the Android host draws. `TouchCollectionEntry` registers `TouchCollectionPanel` with the Overlay Panel Host as `collection`; its host services are bundled in `TouchCollectionData`: the card catalog (`ICollectionCardCatalog`), the run reads (`ICollectionRunReads`) and the supporter rotation (`ISupporterRotation`), which only the Android host binds and so live in the Mobile UI tree, and the Core ports for the source catalog, the day-tier source, the hero preference and the encounter state. Its grid and inspection show the game's own cards through the port's card rental, laid out by Core's `CollectionTouchLayout` ([mobile-ui.md](mobile-ui.md)); the grid packs `CollectionGridLayout` into the column count that keeps a card readable at its width instead of the desktop's fixed count. It differs from the desktop: search drops the `{ability.*}` placeholders instead of resolving them; the inspection renders the rented card and its preview data instead of locking the game's tooltip; and cards scrolled past the grid's edges are covered, not masked.

The Android host binds `src/BazaarPlusPlus.Android/Collection/` ([android-host.md](android-host.md)): `AndroidCollectionCatalog` over `AndroidCollectionCardProjection` and `AndroidCardFacets`, the embedded source catalog against `AndroidCardFacets.IsHeroAvailable`, and a day-tier source that reads the run's day only in a run, because the game keeps the last run's object in the main menu. It reads no day-tier weights, so the Day gate gets the day but no tier and fails open, and no encounter ids (`NoEncounterState`), so no source is pre-selected and no merchant is marked encountered. While the open panel waits, the catalog builds for `CollectionCardCatalogBudget.WaitingFrameBudgetMs` a frame; the host warms it ahead of the first open.

Each touch grid cell reserves space beneath its native card for the localized name. The Mobile UI's `NativeSkin` draws with the popup button sprites and tooltip frame art the host borrows without native callbacks (`AndroidNativeArt`); missing art falls back to the host palette, and destroyed assets trigger a rebuild on the next open. A native button beside the Items tab credits one supporter using the host's supporter rotation (`ISupporterRotation`) and tier colors, and opens the website support page via `BPPSupporterLinks`. Each open advances the rotation once; a late catalog fills the credit without resetting filters, and an unavailable list leaves a Sponsor action. The left-hand rail has a 16 dp inset. Hero and merchant (trainer for skills) selectors share its first row, with native portraits and localized names; a divider separates their choices from size and quality filters below. The port's `EncounterName` reads merchant and trainer titles from their representative encounter templates, falling back to the source catalog name while game data is unavailable. Their options expand below that row one group at a time and collapse on selection; selecting the current choice preserves it. The port's portraits load default hero skins and encounter portrait art (on Android `AndroidPortraits`, in Global scope through the main-thread task bridge), coalescing requests across rail redraws; absent art uses a neutral group icon. Half-width identity buttons place framed portraits above single-line names on a shared baseline; disclosure arrows align with the portraits. Both hero and source options use the same full-width rows, with portraits beside names. `PortraitView.FramePortrait` normalizes sprite-mesh bounds: Vanessa and Pygmalien use an upper-body crop, while other heroes and encounters retain their complete silhouettes with breathing room. Source textures stay unchanged. Reset, run-day, sort, keyword, and tag controls live under More, placed directly after the quality chips with an active facet count while folded. A search redraws the rail only when the run day or the source selector's availability changed, since the facets come from the whole catalog. Expanding More reveals the reset action first and scrolls it fully into view; collapsing returns the rail to the top. `TouchCollectionInspection` shows content-sized native badges for size and deduplicated template tags, preview cooldown and ammo in a larger value row (the port's `CardPreview` builds each tier's text and values from one tooltip), then game-rendered effects above the secondary enchantment list. The content shares one inset; native effect icons and enchantment names align on their first text baseline. It compares every reachable tier through `CollectionTierTooltipTextMerger.MergeLines`: changing numbers share a line with tier colors and the native Fusion separator; unchanged values appear once. The card art stays at its starting tier with no applied enchantment. A 56 dp toggle row with a 32 dp switch expands all available enchantment effects beneath the base description, with the same colored labels as desktop in a separate name column. The port's `EnchantmentEffects` uses the in-game enchant preview renderer at every reachable tier with no run context, on the card's template looked up once; only enchantment-authored effects are listed and changing values are merged. Results are computed on first expansion and discarded for the next card; the toggle does not change in-game preview settings. The inspection expands from the tapped cell after its preview rental becomes ready, then returns to that cell on Back or an outside tap. The grid stays still during inspection; teardown cancels the transition and restores the source card before releasing rentals. `InspectionTransition` owns interruptible timing; the port's `AnimationsEnabled` honors Android's Remove animations setting. Back remains available while opening. Missing attributes are omitted, and rich-text sprites are bound before text height is measured. Android's `AndroidCardRentalBackend.FitSkillMask` insets the skill prefab's existing circular stencil beneath its metal frame once per pooled instance, preserving the artwork rectangle; it never clips the frame itself.

CollectionPanel is a full-screen Item/Skill catalog mounted by `CollectionPanelMount`, registered with the shared Overlay Panel Host (`src/BazaarPlusPlus/DesktopComposition.cs`). Its filter state is pure mutable data: active tab/card type, nullable concrete `SelectedHero` (`EffectiveHero` falls back to `Common`), tiers, tags, hidden keyword tags, Any/All facet modes, sizes, selected source key, run-day filter, and sort priority (`CollectionFilterState`). The tab model contains only `Items` and `Skills` (`CollectionTabKind`).

All filter, search, and catalog state transitions are centralized in the pure `CollectionViewState` reducer: panel command methods are single-line forwards, each returning a `CollectionRenderOutcome?` (`null` = same-value no-op) that the panel consumes at its single `ApplyOutcome` point; grid read-back goes through the injected `ICollectionGridPort`, and hero normalization on catalog accept never writes the hero preference (`CollectionViewState`; behavior tests in `tests/CollectionViewState.Tests/`; load-bearing contract points in ADR-0005). Opening is `Open(CollectionOpenFacts)` and closing is `Close()`; the host then delivers the catalog with `AcceptCatalog` / `CatalogUnavailable` (desktop from its load coroutine, the touch panel on the same frame when cached, else from Tick); a failed hero-preference load opens on the default hero on both hosts. An accept of the list `Open` already took as cached keeps its heroes and facets and only runs the query. A hero choice is staged in PlayerPrefs and written to disk when the panel closes; with the panel still open, the desktop also writes it when the game loses focus, pauses or is destroyed, and the touch panel when the app pauses.

Collection creates one native-card-preview scope for each Unity runtime and gives its virtualizer only that scope. Realized cells retain opaque sessions, not native component/kind/setup-task tuples; stale acquisitions are disposed immediately (`src/BazaarPlusPlus/Game/CollectionPanel/CollectionPanel.cs`, `src/BazaarPlusPlus/Game/CollectionPanel/Grid/CollectionGridVirtualizer.cs`). Runtime teardown waits for pending binds and scope disposal before destroying the overlay and Collection-owned art/material caches (`src/BazaarPlusPlus/Game/CollectionPanel/CollectionPanel.cs`). It runs on a scene change and once a closed panel has stayed faded out for `ClosedRuntimeReleaseDelaySeconds`; the catalog survives it, and the next open rebuilds the view and reloads card art. Collection-specific tooltip registry, cache refcount, and shared-material cleanup remain in its owner adapter and destroy patch, outside the generic preview host.

Collection cards open a modal inspection on left or right click; dragging or scrolling cancels a left click. `CollectionLockVariantPanelPatch` extends native tier/enchantment controls to registered Collection cards when the client supports them. `CollectionInspectionModule` owns an independent preview, suspends Collection input, and closes on Escape or clicks outside those controls. `CollectionInspectionState` rejects stale preview completions and prevents dismissal click-through; `NativeInspectionPresentation` restores borrowed native canvases and raycasters on release. The artwork rectangle stays fixed across tier, enchantment, and description changes until close or viewport resize. Activate the preview behind its alpha gate before measuring the exact native artwork; pooled frame descendants must never affect its fit. The description is re-measured and re-centred only while `CollectionInspectionLayoutSettle` holds the layout dirty: on open, on a tier or enchantment change, on a new preview, on a viewport resize, when a TextMeshPro text inside the description changes its mesh, and when the tooltip or its content rect changes size. It settles once the opening motion is done and two frames measure the same bounds centred on their target. A settled layout is re-checked every `RecheckFrames`; a description change that fires none of those sources (an image or section toggled without a text or size change, an alpha fade) relies on that recheck and stays stale until it runs (`src/BazaarPlusPlus/Game/CollectionPanel/CollectionInspectionLayoutSettle.cs`; `src/BazaarPlusPlus/Game/CollectionPanel/CollectionInspectionModule.cs`; `src/BazaarPlusPlus/Game/CollectionPanel/CollectionInspectionLayout.cs`; `src/BazaarPlusPlus/GameInterop/CardPreview/NativeCardPreviewArtworkMeasurement.cs`; `src/BazaarPlusPlus/GameInterop/Tooltips/NativeInspectionPresentation.cs`; `src/BazaarPlusPlus/Patches/CollectionPanel/CollectionLockVariantPanelPatch.cs`).

Cell measure/fit is split out of the virtualizer: `CollectionCardFitMath` is pure fit math (scale plus anchored position), `NativeCardCellFitter` is the Unity measurement adapter (frame-container → raw-image → aspect-fallback → rect chains), and `NativeCardCellBoundsCache` caches per-cell visual bounds with three invalidation hooks (rebind, scale-dirty, art-load completion) so the scroll path repositions with `allowMeasure: false` instead of remeasuring every realized cell each frame (`src/BazaarPlusPlus.Core/Game/CollectionPanel/Grid/CollectionCardFitMath.cs`, `src/BazaarPlusPlus/Game/CollectionPanel/Grid/NativeCardCellFitter.cs`, `src/BazaarPlusPlus.Core/Game/CollectionPanel/Grid/NativeCardCellBoundsCache.cs`, `src/BazaarPlusPlus/Game/CollectionPanel/Grid/CollectionGridVirtualizer.cs`).

Filtering is code-owned and deterministic. `CollectionFilterEngine.Apply()` applies active card type, excludes package cards from normal results, applies source offer pool membership, hero, tier, day, tag, keyword, and size filters, then sorts by tier/size priority plus localized display name, compared through the name ranks `CollectionCardNameOrder` assigns once per accepted catalog and culture (`CollectionFilterEngine`). Tag and keyword facets support `Any` and `All` matching, and the UI exposes mode toggles in the tag and keyword headers (`src/BazaarPlusPlus/Game/CollectionPanel/Ui/CollectionPanelView.Tree.cs`).

The Day gate consumes only the shared GameData result's `MaximumTier`; absent, not-ready, missing, invalid, and out-of-run results fail open. The manual Tier filter remains an independent AND condition, fixed-tier sources suppress only the Day gate, and Legendary starting tiers retain the game's Diamond compatibility alias (`CollectionFilterEngine`, `CollectionFilterContext`).

Merchant and trainer source filtering is driven by an embedded `collection-sources.json` catalog. Mismatched `collection-sources.json` schema versions are rejected during build/parse. Each source has `offerSegments`, and each segment parses a typed rule with hero mode, starting tier, sizes, tags, hidden tags and groups, enchantability, and enchantment facets (`CollectionSourceCatalog`). A hero the game build lacks is known but unavailable: a fixed-hero entry naming it is skipped, not rejected.

Card VMs project base card tags and per-enchantment facets from game templates; a template whose type, size, or tier has no facet is rejected from the catalog. Lifesteal is derived when an item has positive Lifesteal base value at any tier even if the template lacks the hidden tag (`src/BazaarPlusPlus/Game/CollectionPanel/Data/CollectionCardVmProjection.cs`, `src/BazaarPlusPlus/Game/CollectionPanel/Data/CollectionDerivedKeywordFacts.cs`; tests in `tests/CollectionCardProjection.Tests/`).

Collection and EncounterPreview share `BppStaticCardMapProvider`, which normally uses the native `GetCardMap()`. `CardTemplateValueCompatibilityPatch` prepares the native thread-local card serializer for both bulk and point lookups. `CompatibleCardValueConverter` is installed only when the native `BazaarJsonDerivedTypeConverter.TypeMapping` lacks that discriminator (a failed reflection read installs it); once installed it prefers native value implementations and supplies `TReferenceValueUniqueCardCount` only when the client cannot deserialize it. It counts distinct template IDs while inheriting native target selection, default values, modifiers, and rounding; it does not register a global discriminator or alter GameData on disk (`src/BazaarPlusPlus/GameInterop/StaticCards/`).

Other unknown derived types remain unsupported. If native bulk loading encounters one, `CompatibleCardMapReader` reads the same database in read-only mode with the same value compatibility adapter and omits only unsupported templates. This partial snapshot does not replace the game's cache; malformed data and wholly unsupported catalogs still fail. `static_cards.catalog.unsupported_templates` records accepted and unsupported counts.

Android's disk catalog identity uses the projection version owned by `AndroidCollectionCardProjection.CacheVersion`, alongside the game version, language and manifest ETags. Unrelated mod builds reuse it. Changes to eligibility, facet mappings, derived keyword/mechanic rules, enchantment projection, localized/search text or persisted VM semantics must bump that version; a cache schema change still belongs to `CollectionCatalogCacheStore`. A true cold miss still projects native templates on the main thread.

## Gotchas

Traps and rules that bite only this feature; most failed silently at least once.

- UI Toolkit draws a `Sprite` background through the sprite's tight mesh, and drew several merchant and trainer portraits that way as displaced fragments, though each mesh matches its UVs. Each encounter portrait is an unpacked sprite that fills its own texture, so a source cell draws the texture instead (`SourcePortraitBackground`). [`src/BazaarPlusPlus/Game/CollectionPanel/Ui/CollectionPanelView.Filters.cs`]
- While a desktop source fold is open, the Collection reports modal input to the Overlay Panel Host so that Escape closes the fold first; the host then drops panel hotkeys and the Walkthrough Control's `open` until the fold closes (`just mod::ui-shots` times out). [`src/BazaarPlusPlus/Game/CollectionPanel/CollectionPanel.cs`]

- UI Toolkit `Button` inherits `TextElement`, so `Q<TextElement>()` returns the button itself when no separate label exists — hiding that "label" hides the whole control (guard with `!ReferenceEquals`), and a refresh writing `Button.text` resurrects the native label beside a custom one. [`src/BazaarPlusPlus/Game/CollectionPanel/Ui/CollectionPanelView.Filters.cs`]
- The hardcoded `DayTierSchedule` was removed — do not restore it as a fallback. Day tiers resolve through `GameDataDayTierResolver`, whose success cache is keyed on `JsonGameDataManager` reference identity because the game swaps that reference after a GameData download. [`src/BazaarPlusPlus/GameInterop/DayTiers/GameDataDayTierResolver.cs`]
- Aspect-fallback collection cards (no measurable frame or raw-image bounds) hold size via a one-shot `SetSizeWithCurrentAnchors` plus the per-cell bounds cache. This path shipped without in-game smoke; on card-size drift, apply the fallback documented in the fitter header. [`src/BazaarPlusPlus/Game/CollectionPanel/Grid/NativeCardCellFitter.cs`]
- CollectionPanel source filtering runs off the embedded `collection-sources.json`, and the catalog size is pinned by the source/merchant/trainer count assertions in its test — adding a source means updating those expectations too. [`src/BazaarPlusPlus.Core/Game/CollectionPanel/Sources/CollectionSourceCatalog.cs` | `tests/CollectionSourceFiltering.Tests/Program.cs`]
