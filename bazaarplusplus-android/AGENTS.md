# AGENTS.md

The BazaarPlusPlus Android App (`com.bazaarplusplus.android`) loads the installed official The Bazaar in its own process and starts LemonLoader and the mod in it. Read root `docs/adr/0012-android-app.md` before changing how the App loads the game, what it carries, or what it writes for the mod. Name things with the terms in `GLOSSARY.md` and the root `GLOSSARY.md`.

## Where a change goes

- Mod features and the Android Host belong in `bazaarplusplus-mod/`. This project only finds, loads and launches the game, and stages what LemonLoader reads.
- Tool versions live in `toolchain.lock.json`; Gradle's own version lives in `gradle/wrapper/gradle-wrapper.properties`. The build scripts read the lock, so a version change is one edit there.
- What the App carries (the Loader Release, native libraries, the Updater) is staged by `release/android-app.mjs`, not by Gradle. Gradle only packages `-Pbpp.runtimeDir`.
- `res/values/bpp_tokens.xml` and `res/drawable/bpp_mark.xml` are generated by `design/build.mjs` (`just design::build`). Change `design/tokens.json` or `design/bpp-mark.svg`, never the generated files.
- The bridge Activity (`src/bridge/`) is compiled into `bridge.dex`, which the game class loader defines next to the game's APKs. It must stay out of `classes.dex` and reach App code only by reflection on `GameSession.wrap`.

## Verification

`just android::check` and `just android::test` gate every change (JDK and Android SDK per `toolchain.lock.json`). A change to loading, the runtime or `LoaderDeployment` is done when the debug App launches the installed game on an arm64 emulator:

1. `just android::stage-runtime`, then `just android::install`.
2. For a BPP launch, `just android::interop-package` and `just android::push-interop`.
3. The launcher's BPP launch reaches the game's sign-in screen or main menu, and `adb logcat` shows LemonLoader's `Applied packaged deployment` with no `FATAL EXCEPTION`.

## Gotchas

- The debug App (`com.bazaarplusplus.android.dev`) is a separate sandbox: its game sign-in, Data Root and LemonLoader files are its own.
- A file that `adb push` puts in the App's external files directory belongs to `shell`, and the App cannot read it. Use `push-interop`, which copies through `run-as` into internal storage.
- Unity reads `libmain.so` from `nativeLibraryDir`, so `useLegacyPackaging` (extracted native libraries) must stay on.
- Game logs can hold account data. Quote only the lines you need; never commit or share raw logs.
