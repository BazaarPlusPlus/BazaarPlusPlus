# AGENTS.md

The BazaarPlusPlus design system: the one source for design tokens, the shared `bpp-*` component stylesheet, the Web component library, the brand book and writing standard, and the brand mark. Repo-wide rules are in `../AGENTS.md`; the Chinese summary for contributors is `../docs/design.md`.

| File | Owns | Consumers |
|---|---|---|
| `tokens.json` | Every colour, spacing, radius, size, shadow, motion and font-stack value | `bazaarplusplus-installer/src/styles/tokens.css` (generated), which the site and UI documentation site copy; the Tailwind bridge `tailwind-theme.css` (generated), which all three Web consumers import; the `ingame-*` colours generate the mod's two `InGameTheme.g.cs` files instead, and `control-*`, `badge-height`, `space-*` and the `ingame-text-*` sizes the Desktop UI's `InGameSizes.g.cs`; the product colours, spacing, radii, sizes and type sizes also generate the Android App's `res/values/bpp_tokens.xml`; the server's verification emails import it directly (`bazaarplusplus-server/src/modules/account-email.ts`) |
| `components/bundle.css` | The shared `bpp-*` classes | Imported by `bazaarplusplus-installer/src/styles/index.css`, `bazaarplusplus-site/src/styles/global.css` and `bazaarplusplus-ui-docs/src/styles/global.css` |
| `ui/` | The Web component library: one React implementation of each shared component, drawn only with `bundle.css` classes | The installer, site and UI documentation site, as `@bpp/ui` (a Vite alias and a tsconfig path in each) |
| `ui-classes.ts` | The check that a component's classes exist in a stylesheet | Each product's `bundle-classes` test |
| `README.md`, `writing.md`, `components/*/README.md` | Visual rules, alignment, voice, glossary and component guidelines | Both products |
| `kit-art.ts`, `components/InGameKit/art/material.png`, `art/marks.png` | The Desktop Kit's plate art (one silhouette and material, drawn per state) and its five run and battle marks | The mod's embedded `Resources/DesktopKit/*.png` (generated by `just design::kit-art`) |
| `assets/Logos/bpp-mark*.svg` | The brand mark | Installer title bar, About and Install pages; the Android App's generated `res/drawable/bpp_mark.xml`; the server's verification emails (generated PNG `bazaarplusplus-server/src/modules/email-mark.g.ts`) |
| `assets/Covers/the-bazaar/*.jpg` | The launcher's cover art | The Android App's copies in `res/drawable-nodpi/` |

## The Web component library

`ui/` has no `package.json` and no build; each product compiles it as its own source ([ADR-0018](../docs/adr/0018-one-web-component-library.md)).

- A component goes here when both products render it, or when its spec lives in `components/` and nothing in it is product-specific. A component that reads a product's data, router, i18n or modal stack stays in that product and composes these. The card catalog (`game/catalog.tsx`), the game terms (`game/terms.ts`) and the Run replay wiring (`game/Decisions.tsx`) are the same for both products and live here ([ADR-0025](../docs/adr/0025-card-catalog-in-the-ui-kit.md)); a product passes its card source, its modal host and the Run's own data.
- Draw only with `bundle.css` classes. Tailwind does not scan `../design`, so a utility class here renders unstyled; the `bundle-classes` tests fail on any class `bundle.css` does not define.
- Copy comes in through props; the library's only strings are the game terms in `game/terms.ts`.
- Import only `react`, files in `ui/` and the root `runs/` sources (by relative path). Files here resolve React from the importing product (`resolve.dedupe`, the tsconfig `react` path), so a second runtime dependency would have nowhere to resolve from.
- Tests live in the products, which have jsdom: the installer's `src/components/ui/library.test.tsx` covers behaviour. `ui/tsconfig.json` and `ui/vite.config.ts` give it its own type check and lint, which the root `typecheck` and `lint` scripts run.

## Changing the system

- Edit the file that owns the value, run `just design::build`, and commit the regenerated `tokens.css`, `tailwind-theme.css` and Android resources with it. `just design::check` fails on a stale `tokens.css` or `tailwind-theme.css`, a Desktop Kit plate PNG that differs from what `kit-art.ts` draws, a stale cover art copy, a `var()` in `bundle.css` with no token, a px font size in `bundle.css`, a site hero colour that disagrees with its `hero-*` token, a supporter colour in the mod's `BPPSupporterAttribution` that disagrees with its `ingame-*` token, an Android launcher icon exported from an older desktop app icon, or a stale email mark PNG.
- A change to tokens, `bundle.css` or `ui/` also passes the installer's, the site's, the UI documentation site's and the Android App's check and test recipes (a token change, the mod's and the server's too), and regenerates the installer shell goldens (`BPP_UPDATE_GOLDENS=1`) and, for a visible site change, the site's Linux screenshot goldens (`bazaarplusplus-site/AGENTS.md`).
- Live component previews and design token tables are published at https://ui.bazaarplusplus.com (`bazaarplusplus-ui-docs/`).
