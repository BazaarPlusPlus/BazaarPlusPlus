# BazaarPlusPlus Site Architecture

The code is the structural source of truth. This document records intended ownership and cross-module contracts that are costly to infer from individual files.

## Ownership

| Concern | Owner | Boundary |
| --- | --- | --- |
| URL and browser history | `src/app/router.ts` | Owns routes, aliases, locale and Analysis Scope parsing, canonical hrefs, click eligibility, and push/replace/popstate behavior. |
| Page composition | `src/app/App.tsx` and `src/app/route-pages.tsx` | Render the resolved location; `/heroes`, the account pages and `/records/<run_id>` stay lazy, guarded by the route chunk golden in `e2e/__snapshots__/route-chunks.json`. The Run detail chunk alone carries the Run segment decoder. Runtime data enters through React Query. |
| Hero Metrics Dataset ingestion | `src/features/heroes/hero-metrics-dataset.ts` | Owns the snapshot fetch and its timeout, decoding, compatibility, and Dataset Coverage. Retries belong to the `/heroes` query in `src/app/route-pages.tsx`. |
| Account requests | `worker.ts` | Forwards same-origin `/api/*` through the server WebApi service binding in preview and production. |
| Card Art and Card Text | `worker.ts`, `src/features/runs/card-art.ts` and `src/features/runs/card-text.ts` | The Worker serves `/card-art/*` from `cdn.bazaarplusplus.com/card-art/` through the Cache API: only `index.json` (1 h, stale-while-revalidate) and content-addressed art and locale files (immutable); only a 200 is cached. The page reads the index through React Query, takes card titles from its `names` (GameData, every card type) and falls back to the name when art is missing. Hovering or focusing a card shows its definition beside it, and opening one shows it in a dialog; either first fetches the index’s locale file by filename. The page resolves each card’s shared enchantment positions and combines the definition with the captured tier and enchantment. |
| Account pages | `src/features/account/` | Owns sign-in by email and password, registration and password reset by emailed code, the profile (Bind Code, unlinking, account deletion), the records page and sign-out. A Record is one of the linked game account's ranked Runs of the last 8 days (root `GLOSSARY.md`); `/api/runs` returns all of them at once, and `records.ts` sorts them by end time and derives the totals, the rating line, the hero table and the day groups in the browser. `account-api.ts` is the only `/api/*` client. `turnstile.tsx` loads the Turnstile script only on the sign-in, registration and reset pages and spends one token per submit; the site key comes from `VITE_TURNSTILE_SITE_KEY` at build time (`deploy-site.yml`), else Cloudflare's always-pass test key. |
| Run detail | `src/features/runs/` | `run-payload.ts` decodes the Record's Run segment in the browser (gzip, 64 MiB cap, payload version 6, Run id); `run-timeline.ts` derives each Battle's board and its change from the last observed board by InstanceId. The page only renders that model. |
| Decision path | `../runs/message-stream/` | Reads Run segment key 8 lazily, after the page shows: `wire.ts` undoes the game's Lz4BlockArray, `translate.ts` names every value with the Game Message Schema and keeps what it cannot name raw and flagged, `project.ts` folds the frames into per-hour steps (a command counts only with evidence from its paired responses; a GameStateSync is a new baseline; an undecodable message suspends inferences until one). Every frame stays reachable from a step as readable JSON. The schema and translator load in their own chunk. |
| Game Message Schema | `../runs/tools/message-schema/` | `extract.cs` (System.Reflection.Metadata) reads a Game Assembly Snapshot; `generate.ts` merges it into the committed `game-message-schema.json`, cumulative across builds. `just site::check` only checks that the file is what the generator writes for the sources it records; a new game build is merged as an ordinary site change, and until then its new keys stay raw and flagged. The Snapshot Lock pull request stays lock-only (root ADR 0015). |
| Hero Analysis | `src/features/heroes/hero-analysis.ts` | Pure, React-free policy for scope selection, merging, ranking, trends, matchups, focus fallback, and selected-window coverage. |
| Hero Analysis presentation | `src/features/heroes/HeroOverviewDashboard.tsx`, `HeroTrendPanel.tsx`, and `HeroRankingTable.tsx` | The dashboard composes validated analysis and shares hero focus. The trend module owns SVG geometry and chart interaction; the ranking module owns its columns and sorting policy. |
| Installer resolution | `src/features/download/installer.ts` | Owns the Platform Release Manifest fetch and primary-download decoding, one manifest per platform. The workspace `release/downloads.ts` owns release origin, platform keys, manifest paths, the mainland mirror decoder `decodeMainlandDownloadUrl` and the Android decoder `decodeAndroidDownload`; the download page consumes the resolved per-platform model. |
| Game Status | `loadGameStatus` in `src/features/download/installer.ts` | Reads what Steam's public branch holds now (root `GLOSSARY.md`) for the desktop cards. A failure hides its rows and never touches the download. |
| Visual system | `src/styles/tokens.css`, `../design/ui/` and `src/shared/components/` | The `:root` tokens come from `../design/tokens.json`, generated into the installer's `src/styles/tokens.css`, which the `tokens` script copies to the git-ignored `src/styles/installer-tokens.css` before `dev` and `build`. The site's `tokens.css` imports the Tailwind bridge `../design/tailwind-theme.css`, which `design/build.ts` generates, and adds only the site's black, white and dialog animation; components take color, font, size, radius and motion values only through these utilities. `src/styles/global.css` imports `../design/components/bundle.css`. Features compose `Button`, `Badge`, `StatusPanel` and `Dialog` from the Web component library (`@bpp/ui`, root `docs/adr/0018-one-web-component-library.md`) and `PageLayout` and `HeroBadge` from `src/shared/components/` instead of restating their classes. |
| WeChat Pay QR artwork | `../bazaarplusplus-installer/static/support/wechat-pay.svg` | The installer owns the SVG; `src/features/support/SupportPage.tsx` imports it as raw markup so both projects display the same payment code. |

Presentation modules consume resolved models; payload decoding stays in ingestion and browser-history handling stays in the router.

Installer resolution reads each platform's Platform Release Manifest at `latest/<platformKey>.json` (paths from `platformManifestPath` in workspace `release/downloads.ts`) rather than reconstructing primary filenames, so each card carries its own version and the platforms may differ. Primary URLs must belong to the expected origin, that manifest's version and its platform; a platform whose manifest is missing or invalid degrades only its own card, and the GitHub fallback appears only when no platform loads. The mainland mirror address is the manifest's `downloads[platform].mainlandUrl`, read through `decodeMainlandDownloadUrl` in workspace `release/downloads.ts`, the same decoder the desktop installer uses; a manifest without it disables only the mirror entry. The Android card has the same mirror entry. The Android card reads `latest/android-aarch64.json` through `loadAndroidRelease` and is always on the page: while that manifest is missing or invalid it degrades like a desktop card (an unavailable version and a disabled download, keeping its experimental notice, feedback group and install steps), and its failure never raises the page-level GitHub fallback. Writer and consumer share the fixtures under `release/fixtures/latest/` at the workspace root; publish a complete manifest before deploying a website that requires this contract.

## URL Contract

- `src/app/router.ts` is the route catalog for App routing, navigation, and page-title keys. Cloudflare supplies SPA fallback; unknown paths still resolve to the localized not-found page.
- The My records navigation link opens `/records`, and stays current on `/account` and `/records/<run_id>`. A signed-out response (401 `unauthorized`) on any account page replaces it with `/login` in the current locale. Sign-in, registration and password reset replace their page with `/account`; sign-out and account deletion replace it with `/login`. `/account` and `/records` link to each other.
- `/records/<run_id>` is the one parameterized route; the router decodes the Run id.
- Default values—Chinese, `1d`, and `all`—omit `lang`, `w`, and `s`; non-default values serialize explicitly.
- Hero Analysis query values canonicalize at the SPA location boundary independently of page data loading.
- Analysis Scope changes and alias canonicalization replace history. Internal navigation pushes. Locale links preserve the current path, scope, and hash.

## Hero Metrics Dataset

- `loadHeroMetricsDataset` fetches the snapshot and is its only decoder. A non-2xx response throws `HeroMetricsHttpError` with the status, so the `/heroes` query never retries a 4xx; network failures, 5xx, timeouts, and undecodable snapshots are retried.
- One snapshot contains 1–7 contiguous daily entries. Its inclusive `window.end`, rather than the wall clock, governs window selection and freshness.
- Additive fields and non-canonical heroes are compatible. An invalid envelope fails the page; an invalid daily entry degrades Dataset Coverage under `GLOSSARY.md` semantics.
- Snapshots store `legend` and `non_legend`; analysis derives `all` by additive merge.
