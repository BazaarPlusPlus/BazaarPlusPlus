# Stream Service

## Native Lifecycle

- `StreamRuntime` in `src-tauri/src/stream/runtime.rs` is the single owner of service lifecycle, task handles, and captured installation paths. Its lifecycle mutex serializes ensure, restart, stop, window changes, and exclusive maintenance.
- `StreamRuntime::ensure` and `StreamRuntime::restart` resolve one selected-installation snapshot on the blocking pool, then take the lifecycle gate with it. `StreamRuntime::prepare_history_thumbnails` resolves under the gate, and only when it has to start the service. Window changes reuse the captured record path rather than resolving a different installation mid-session, and query the record database on the blocking pool.
- `ProductionServer::start` in `src-tauri/src/stream/server.rs` creates the repository and settings store, binds the loopback service, reports database availability, and serves with graceful shutdown. `origin` in the same file is the one service origin every URL is built from; the service binds that fixed port or fails.
- `StreamRuntime::prepare_history_thumbnails` is the History List's entry to the same lifecycle: it starts a stopped service and never rebinds a running one.
- Startup, tray actions, window-close behavior, and Tauri stream commands call through `StreamRuntime`; they do not mutate the server task directly.
- Stream command failures are classified by capability and operation in `src-tauri/src/commands/stream.rs` and returned as `SemanticProblem`.

## Frontend Capabilities

`DefaultStreamWorkflow` in `src/features/stream/streamWorkflow.ts` keeps service state, polling freshness, display window, crop settings, and one-off actions independent. Repeated poll failures retain the last value but mark it stale; actions that require authoritative running state remain gated until a successful refresh. Problems and notices stay semantic until `src/features/stream/streamProblems.ts` and `src/features/stream/streamPresentation.ts` translate them.

Closing the main window while the service runs hides it to the tray, and the page stays mounted. A WebView hidden that way need not report `visibilitychange`, so `hide_to_tray` in `src-tauri/src/main_window.rs` emits `main-window-hidden` after the hide. `useStreamPage` pauses status polling on that event or a hidden page (`observeWindowHidden` in `src/features/shared/windowActivity.ts`) and, as soon as the window regains focus or the page becomes visible (`observeWindowResume`, which listens for visibility in every mode because a page can become visible without focus, as an uncovered macOS window does), polls at once and resumes the interval. The Windows title bar's close copy comes from `useShellStreamServiceRunning`, which never polls: it reads the status on mount, on window resume, and when the pointer or focus reaches the close control.

## HTTP Surface

`router` in `src-tauri/src/stream/http.rs` serves the overlay, settings, record and crop APIs, record images, and static assets, and merges the History Thumbnail route. CORS is restricted by `is_allowed_cors_origin` to Tauri origins and the configured local Vite development origins.

Every handler's database, image, and overlay settings file access, including the crop API's settings read and write, runs on blocking threads through `run_record_task`, never on the async workers shared with Tauri commands: a SQLite open can wait out the busy timeout while the game holds a lock, and file reads and writes block. The OBS strip route makes one blocking hop into `render_strip` in `src-tauri/src/stream/strip.rs`, which reads the saved crop, resolves the record's screenshot, and crops, caches, and encodes the PNG. A crop in the query is validated before that hop and overrides the saved crop; `preview=true` bypasses the cache.

The OBS overlay polls the record list and the crop API every few seconds for as long as OBS shows it, so each repeated step is kept cheap. `OverlaySettingsStore::load` reuses its last parse while the settings file keeps the same modification time and length; every `Default` store shares one memo, which any save clears. Record reads always query SQLite: in WAL mode the database file's modification time and size do not follow commits, so they cannot tell a new record apart. When the service has no record installation, `OverlayRecordRepository` reuses a failed search of the known Steam libraries for `DATABASE_MISS_TTL` before scanning again. The overlay page leaves an unchanged empty state's DOM alone.

The History Thumbnail route belongs to `src-tauri/src/stream/history_thumbnails/mod.rs`, which also owns its source registry and URL builder. It always uses the saved crop. Both routes cache under their own directory of the cache root, `HISTORY_THUMBNAIL_CACHE` or `OBS_STRIP_CACHE`, in one namespace per installation path named by a digest of that path (`cache_namespace`). Each route keeps its own `SourcePaths`, a bounded memo of each screenshot's source image, so a repeated request skips SQLite: the History Thumbnail route's lives on `HistoryThumbnails` for the whole process, and the OBS strip route's in the router state for one service run. The two are separate because the OBS route serves only end-of-run captures. A remembered file that is gone is looked up again, so a deleted screenshot is still not found. The cache key still reads the source's size and modification time, so a replaced image renders again. Both share `cached_strip`: writes go through a uniquely named temporary file, and a hit refreshes the entry's modification time only once the entry is older than `REFRESH_AFTER`, one day: short enough that the count cap, which removes the oldest modification times across both caches, still keeps a strip OBS shows all the time over thumbnails viewed once. `sweep_cache` in `strip.rs` runs once per process on a blocking thread when the service first starts. It deletes orphaned temporary files and strips unused past an age limit in both caches, then the oldest beyond one count cap across both, and the OBS strips that earlier versions left at the cache root itself; it skips files modified in the last few seconds, and every deletion is best effort because Windows refuses to delete an open file. The limits are `CACHE_LIMITS` in that module.

Overlay records carry canonical `hero_id` separately from their display title through `to_overlay_record` in `src-tauri/src/stream/records/mapper.rs`. The settings page owns a small zh/en dictionary because it runs on the service origin; `DefaultStreamWorkflow.openSettings` appends the current app locale when opening it.
